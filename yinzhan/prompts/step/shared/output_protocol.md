# 通用输出协议（跨步骤共享）

> 本文件定义所有分析步骤共用的输出规则。各步骤提示词（analyst_prompt、natal_module_skeleton、md_prompt、ad_prompt）引用本文件，不重复其内容。若具体步骤提示词与本文件冲突，以本文件为准。

---

## §1 证据标记体系

按分析层级递进，每个层级**严禁混用**其他层级的标记前缀：

| 层级 | 正证 | 反证 | 适用范围 |
|------|------|------|---------|
| 本命基线（步骤 1-4） | E# | CE# | 基线分析 |
| 本命领域模块（步骤 6-x） | ME# | MCE# | career、wealth 等本命模块 |
| 大运总控 | TE# | TCE# | md_general |
| 大运领域模块 | DE# | DCE# | career_md、wealth_md 等 |
| 子运总控 | AE# | ACE# | ad_general |
| 子运领域模块 | ADE# | ADCE# | career_ad、wealth_ad 等 |
| PD 钻取 | PDE# | — | pd_drilldown |

## §2 证据引用与回链格式

### 2.1 上游引用

引用上游证据时使用 `[Ref: {module}.{标记}]` 格式，不得将上游标记直接用于本层。

示例：
- `[Ref: 2-1.E3]` — 引用基线步骤 2-1 的证据 E3
- `[Ref: career_ME#2]` — 引用本命事业模块的证据 ME2
- `[Ref: md_general.TE#1]` — 引用大运总控的证据 TE1
- `[Ref: career_md.DE#3]` — 引用大运事业模块的证据 DE3
- `[Ref: ad_general.AE#2]` — 引用子运总控的证据 AE2
- `[Ref: {domain}_A3.事件类型]` — 引用某模块 A3 的特定事件类型

### 2.2 引用格式硬规则（违反即不合格）

- 唯一正确写法：`[Ref: 2-1.E6]` — **方括号开头**，Ref 后带**冒号**，步骤号.证据号，**方括号结尾**。
- 禁止：`Ref(2-1.E6)` — 圆括号。
- 禁止：`Ref(E3)` — 圆括号且缺步骤号。
- 禁止：`[Ref E3]` — 缺冒号且缺步骤号。
- 禁止：`[Ref 2-1.E6]` — 缺冒号。

### 2.3 本层证据回链

B1 每条核心断语必须附证据锚点：`[evidence: XX#]`（XX# 为本步对应层级的证据编号）。

- 如存在显著反证影响，可附：`[counter: CE#]`（不可放在 `[evidence]` 内）。
- 缺少回链 = 检查师判定 revise。

## §3 Part B 现实映射规范

适用于所有步骤的 Part B 白话区（包括 B1 现实断语、B2 触发条件清单、总控 B1 剧情预告等）。

Part B 的核心要求是**每条结论必须有现实映射**，不能只堆术语不落地。允许使用英文行星名、梵文术语、宫位编号和分盘代号作为精确表达，但每条术语断语必须紧跟可观察的现实事件描述。

### 3.1 禁止的写法（纯术语堆砌，无现实映射）

| 禁止 | 应该写为 |
|------|--------|
| 5/8/11 链联动 | 5/8/11 链联动——投机运与他人之财的通道打开，可能体现为股权收益或配偶带来资产 |
| Rahu 放大 7H | Rahu 放大 7H——合作关系中容易出现过度承诺或被对方包装的外表误导 |
| Venus 落陷 + D9 弱 | Venus 落陷 + D9 状态弱——感情中容易反复妥协，底线较低，可能形成“明知不合适但舍不得离开”的模式 |

### 3.2 自检标准

检查 Part B 每条断语：如果拿掉术语部分，还能不能看出具体说的是什么事？如果不能，就说明现实映射不足。

### 3.4 对象分层（Part B 必须执行）

禁止把"伙伴、客户、对手、家人"混写为同一对象，必须显式标注对象类型：
- `伙伴`：合伙/协作方（分工与分账）
- `客户`：交易方（报价、交付、回款）
- `对手`：竞争方（抢单、竞标、压价）
- `家人`：家庭成员（父母、配偶、子女）

## §4 note.md 写入规范

`note.md` 是团队共享的分析笔记，定位与基本规则遵守分析师提示词 §2.4 的统一定义。

### 4.1 步骤完成后的追加模板

每个分析步骤完成后，**视情况**将以下内容追加写入 `workspace/note.md`（无跨步骤影响时可跳过）：

```
### [步骤编号] {步骤名称} — [完成时间]

**核心发现**（1-3 条）：
- ...

**跨步骤待验证点**：
- （如"XX 事件窗口待 AD 层复核"）

**对后续步骤的注意提示**：
- （如"career_ad 注意 MD 星逆行对执行力的削弱"）

**task.yaml 改动摘要**（如有）：
- ...
```

### 4.2 跨模块引用标记

若发现与其他模块强相关的结论，用 `[Cross-Link: module_code]` 标注，不重复分析。

示例：`[Cross-Link: career] 伴侣可能来自工作环境`

## §5 证据格式模板

### 5.1 基线证据（E#）

```
E# | 命题 -> 盘面证据(D1/D9/宫位/相位/Dasha/Nakshatra/SAV/Vimsopaka) -> 限制条件 -> 置信度(critical/high/medium/low)
```

### 5.2 模块证据（ME#）

```
ME# | 命题 -> 盘面证据(分盘/宫位/相位/Nakshatra/Vimsopaka/SAV) -> 限制条件 -> 置信度(critical/high/medium/low)
```

### 5.3 大运证据

- 总控：`TE# | 命题 -> 大运星身份/状态/激活机制 -> 限制条件 -> 置信度`
- 领域：`DE# | [MD星] 触动 [本命配置] -> [化学反应/现象预判] -> 置信度(critical/high/medium/low)`

### 5.4 子运证据

- 总控：`AE# | 命题 -> AD星[具体盘面证据] -> 限制条件 -> 置信度(critical/high/medium/low)`
- 领域：`ADE# | [AD星] 在 [分盘] 的 [状态] + [Transit/PD触发] -> [事件预判] -> 置信度`
- **粒度约束**：同一个 AE# 最多支撑 3 条现实断语，超过则必须拆分为新 AE#

### 5.5 PD 证据

```
PDE# | PD星 × Transit配置 -> 事件锚定 -> 置信度
```

### 5.6 反证格式

```
CE#/MCE#/TCE#/DCE#/ACE#/ADCE# | 反向解释 -> 对应证据 -> 为何不足以推翻主判断 / 如何修正
```
